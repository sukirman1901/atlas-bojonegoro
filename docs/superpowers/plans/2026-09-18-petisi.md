# Petisi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Petisi tab (max 3 active campaigns from P1) with email-verified signatures, UI matching Atlas Bojonegoro, backed by Supabase Auth + Postgres.

**Architecture:** Keep the static atlas on Cloudflare (`public/` + Worker). Petisi data and magic-link auth live in Supabase. The browser talks to Supabase JS client for list/detail/sign; signature rows become countable only after `verified_at` is set via Auth callback. Editorial creation of campaigns is via Supabase Table Editor in v1 (no admin UI).

**Tech Stack:** Vanilla HTML/CSS/JS (`public/`), existing atlas tokens/classes, `@supabase/supabase-js` (CDN or vendored ESM), Supabase Auth (magic link) + Postgres + RLS, Cloudflare Worker unchanged for Lapor.

**Spec:** `docs/superpowers/specs/2026-09-18-petisi-ui-design.md`

- [ ] **Step 1: Write migration SQL**

```sql
-- supabase/migrations/20260918_petisi.sql
create extension if not exists "pgcrypto";

create table if not exists public.campaigns (
  id uuid primary key default gen_random_uuid(),
  slug text not null unique,
  title text not null,
  summary text not null default '',
  demand text not null,
  target_label text not null default '',
  isu_id integer,
  status text not null default 'open'
    check (status in ('open', 'closed')),
  show_public_names boolean not null default false,
  created_at timestamptz not null default now(),
  closed_at timestamptz
);

create table if not exists public.signatures (
  id uuid primary key default gen_random_uuid(),
  campaign_id uuid not null references public.campaigns(id) on delete cascade,
  display_name text not null,
  email_normalized text not null,
  kecamatan text,
  verified_at timestamptz,
  created_at timestamptz not null default now(),
  unique (campaign_id, email_normalized)
);

create index if not exists signatures_campaign_verified_idx
  on public.signatures (campaign_id)
  where verified_at is not null;

alter table public.campaigns enable row level security;
alter table public.signatures enable row level security;

-- Public read campaigns
create policy "campaigns_select_public"
  on public.campaigns for select
  to anon, authenticated
  using (true);

-- Public read verified signature counts via select of verified rows only (names if allowed)
create policy "signatures_select_verified"
  on public.signatures for select
  to anon, authenticated
  using (verified_at is not null);

-- Insert unverified signature as anon (app sets verified_at null)
create policy "signatures_insert_anon"
  on public.signatures for insert
  to anon, authenticated
  with check (verified_at is null);

-- Updates only via service role / later Edge Function; no anon update policy
```

```js
// public/js/petisi.js — top
(function () {
  const cfg = window.PETISI_CONFIG || {};
  let supabase = null;

  function petisiEnabled() {
    return !!(cfg.enabled && cfg.supabaseUrl && cfg.supabaseAnonKey && window.supabase);
  }

  function client() {
    if (!petisiEnabled()) return null;
    if (!supabase) {
      supabase = window.supabase.createClient(cfg.supabaseUrl, cfg.supabaseAnonKey);
    }
    return supabase;
  }

  function normEmail(email) {
    return String(email || "").trim().toLowerCase();
  }

  window.Petisi = { petisiEnabled, client, normEmail };
})();
```

```js
async function fetchCampaigns(sb) {
  const { data, error } = await sb
    .from("campaigns")
    .select("id,slug,title,summary,demand,target_label,isu_id,status,show_public_names")
    .order("created_at", { ascending: false });
  if (error) throw error;
  return data || [];
}

async function countVerified(sb, campaignId) {
  const { count, error } = await sb
    .from("signatures")
    .select("id", { count: "exact", head: true })
    .eq("campaign_id", campaignId)
    .not("verified_at", "is", null);
  if (error) throw error;
  return count || 0;
}
```

### Task 5: Sign + magic link + verify

**Files:**
- Modify: `public/js/petisi.js`
- Modify: `supabase/README.md` (redirect URLs)
- Optional later: Edge Function to set `verified_at` securely

**v1 verify approach (document in README):**

1. Insert signature with `verified_at = null`.
2. `supabase.auth.signInWithOtp({ email, options: { emailRedirectTo: origin + '/?tab=petisi&petisi=' + id + '&verify=1' } })`.
3. On load with session (`getSession`) and `verify=1`, upsert/update signature for that email+campaign setting `verified_at = now()` using a **Supabase RPC** `verify_my_signature(campaign_id)` that runs as `authenticated` and matches `auth.jwt() -> email`.

- [ ] **Step 1: Add RPC to migration (amend file or new migration)**

```sql
create or replace function public.verify_my_signature(p_campaign_id uuid)
returns void
language plpgsql
security definer
set search_path = public
as $$
declare
  v_email text;
begin
  v_email := lower(auth.jwt() ->> 'email');
  if v_email is null then
    raise exception 'not authenticated';
  end if;
  update public.signatures
    set verified_at = coalesce(verified_at, now())
    where campaign_id = p_campaign_id
      and email_normalized = v_email;
end;
$$;

revoke all on function public.verify_my_signature(uuid) from public;
grant execute on function public.verify_my_signature(uuid) to authenticated;
```

- [ ] **Step 2: Form submit handler**

Validate name ≥2 chars, email basic regex; insert signature; call `signInWithOtp`; show `.form-msg-ok` “Cek email untuk mengonfirmasi.” On unique violation, show “Email ini sudah terdaftar untuk petisi ini.”

- [ ] **Step 3: On Petisi render, if `verify=1` and session**

Call RPC `verify_my_signature`, strip `verify` from URL, show thank-you state, refresh count.

- [ ] **Step 4: Manual E2E**

Sign with real inbox → click link → count increments by 1; second sign same email does not double-count.
